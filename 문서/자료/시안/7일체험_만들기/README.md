`build.sh` 가 **늘 깨끗한 바탕부터** 쌓는다. 고친 판 위에 또 덧붙이면 단추·저장이 두 벌이 된다 (10-02 실제로 겪음).

| 순서 | 파일 | 하는 일 |
|---|---|---|
| 0 | `0_바탕_10-01판.html` | 다른 대화가 만든 10-01 판 (피로 엔진 · 스탯 · 업적 · 사진) |
| 1 | `patch7.py` | 운동 화면 '한 화면에 한 종목' · 11 UI지침(글자 · 모서리 · 높이) · 22 버그 #4 |
| 2 | `patch_mark.py` | ✎ 표시 도구 (db `marks` · assets 사진) |
| 3 | `patch_v3.py` | 10-02 표시 7개 — 캘린더 칸 64 · 날짜 판 세로 목록 · 운동 화면 배치 · 이전 단추 |
| 4 | `patch_v4.py` | 10-03 날짜 판 — 종목 6개 이상이면 4줄 + '외 n종목 ∨' 접기 · 운동 시작 줄 붙박이 (기록 날도 같게) |
| 5 | `patch_v5.py` | 10-03 표시 9개 — 날짜 판(예정 이름표 없앰 · 칩 순서 · 변경 위로 · 운동 시작 맨 아래) · 시트 머리 띠 · 플랜 고치기(훈련 방식 단추 · 주당 삭제 · 1RM/무게×횟수 · 저장/닫기) · 꾸준히 늘리기 5세트 × 8~15회 이중 진행 |

시험: `python3 test_v3.py 7day-v4.html` — 캘린더 · 운동 화면 19가지 (10-03 v4 에서도 19/19).
`python3 test_v4.py` — 날짜 판 접기 · 붙박이 13가지 × (높이 900 · 1080 · 어둡게) = 39가지 (10-03 39/39).
`python3 test_v5.py` — 표시 9개 · 이중 진행 계산 27가지 × (폭 420 · 360) = 54가지 (10-03 54/54). v5 에서 test_v3 19/19 · test_v4 39/39 도 그대로.
`python3 render_marks.py [파일]` — ✎ 표시를 그때 상태로 다시 띄워 선을 겹친 사진(`marks2/r_*.png`). 시트가 열린 화면은 html2canvas 사진이 겹쳐 찍혀서 이것으로 본다 (`CLAUDE.md` 2-1 의 3번).
경로는 작업 컨테이너 기준이라 쓸 때 `SP` 경로를 맞춘다. 결과물은 위 폴더의 `../7일체험.html` 과 같다.
