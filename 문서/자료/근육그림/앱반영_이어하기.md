## 설계 안 (Claude — 바꿔도 된다)
1. **자원 만들기** — `tools/근육그림_생성.py` (새로): `그림/` → `app/src/main/assets/muscle/*.webp` (전신은 그대로 · 확대는 768 로 줄임), `대표칸/지도/` → 칸 번호 판(회색 PNG · 값 = (칸 번호 × 2 + 쪽) × 8 · 0 = 빈 곳 · 줄일 때는 최근접), 표는 `ui/MusclePicData.kt` 로 (그림 6장의 이름 · 크기 · 자르기 상자 · 칸 → 값을 정하는 근육). `tools/근육지도_생성.py` 와 같은 방식 — 손으로 고치지 않는 파일
2. **그리기** — 그림 한 장 = 회색 그림 + 칸마다 가림판(그 칸 자리만 불투명). 칸 색은 `ColorFilter.tint(색)` + `BlendMode.Multiply` 로 겹쳐 그리면 명암이 그대로 남는다. 파이썬 `색입히기`(진하기 0.6 · 밝기 기준 92%)와 같게 하려면 곱하는 색 = `min(1, 0.4 + 0.77 × 색)` (채널마다). 칸마다 `animateColorAsState` 로 지금처럼 0.6초 옮김. Multiply 는 minSdk 26 에서 된다(Color · Hue 같은 것은 29 부터라 쓰지 않는다)
3. **칸 값** — 칸에 든 근육의 잎 중 가장 큰 단계(지금 조각 규칙과 같다). 좌우는 같은 값
   - ⚠ 판단 필요: `칸표.json` 은 전거근(`serratus`)을 **복부** 칸에 넣었다(자리를 메우려는 것). 값까지 그대로 따르면 전거근을 쓰는 가슴 종목에서 복부가 칠해진다 → 값은 **가슴** 칸으로 보내는 안
   - ⚠ 판단 필요: 능형근(`rhomboids`)은 어느 칸에도 없다(세부 부위 '등'에는 있다) → **승모** 칸이 대신 칠하는 안 (옛 SVG 의 `대신` 과 같은 방식)
   - 목 칸(`scm` 등)은 세부 부위에 없어 눌러도 빈 목록
4. **누르기** — 칸 번호 판에서 누른 픽셀의 칸 → 그 칸의 세부 부위 목록(가슴 = 위 · 가운데 · 아래 · 전거근 / 어깨 = 앞 · 옆 · 뒤 / 승모 = 승모 · 능형 / 광배 = 광배 · 대원근 / 이두 = 이두 · 상완근 / 종아리 = 종아리 · 정강이 …). 확대 그림을 눌러도 같게
5. **어느 그림을 쓰나**
   - 전신 한 칸('지금 몸' · 근육 없는 종목) = 01 · 02 를 나란히
   - 반신 4가지 = 01 · 02 를 자른다. 자르기 상자를 새로 정해야 한다(그림 좌표 768×1376 — 위: 턱 밑 ~ 배꼽 아래 팔 포함 / 아래: 엉덩이 ~ 발)
   - 확대 = 가슴 → 07 · 팔~어깨 → 04 · 등 → 06 · 하체 → 05. 복근은 그림이 없다(지금처럼 빈 칸)
   - 운동 중 '지금 종목 확대' = `근육두장고름` 으로 고른 확대 그림(없으면 반신, 그것도 없으면 전신) — 지금의 `근육계산.확대상자` 를 대신한다
6. **`data/` 는 건드리지 않는다** — 피로 · 단계 계산은 그대로고 보여 주는 방법만 바뀐다. 옛 SVG 표(`근육자료.조각` · `조각값` · `확대상자` · `부위상자`)와 그 시험(`MuscleTest.kt`)은 남겨 둔다(지우기는 따로 묻는다) → watchdog 은 필요 없다
7. **시험 · 확인** — 표 시험 하나(24개 세부 부위가 모두 어느 칸엔가 걸리는지 · 칸 번호 판의 값이 표와 맞는지) + `MuscleCardsTest` 의 "그림 준비 중" 글 시험 고치기. 화면은 `screens/now` 에서 `Shot_s07*` · `Shot_s08*` · `Shot_s16*` · `Shot_s05b*` 만 찍어 본다
8. `7일체험.html` 시안은 SVG 그대로다 — 앱만 앞서간다는 것을 보고에 적는다
