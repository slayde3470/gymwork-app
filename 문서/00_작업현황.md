## 이 문서를 읽는 분께

이 저장소는 **개인 운동기록 앱**을 만드는 프로젝트입니다.
만드는 사람은 **코딩 경험이 거의 없는 체육 교사**이고, AI(Claude / ChatGPT / Gemini)의
도움을 받아 만들고 있습니다.

**AI가 이 저장소의 작업을 이어받는 경우, 이 문서를 먼저 읽어 주세요.**
지금까지 무엇을 왜 그렇게 정했는지가 전부 여기 있습니다.

### 작업할 때 지켜 주세요

1. **사용자가 답변하지 않은 것 · 확인해주지 않은 것은 임의로 진행하지 말 것.**
   진행 전에 반드시 물어볼 것. (사용자의 명시적 요청)
2. **주석은 한국어로.** 코드가 *무엇을* 하는지보다 *왜 그렇게 했는지*를 쓸 것.
3. **모르면 모른다고 할 것.** 확인이 필요하면 필요하다고 말할 것. 지어내지 말 것.
4. 새로 정해진 것이 있으면 **이 문서를 갱신**할 것.

## 2. 확정된 기술 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 형태 | 웹앱(PWA) + 안드로이드 APK, **코드는 한 벌** | 두 번 만들지 않기 위해 |
| 프론트엔드 | React + Vite | 흔한 기술이라 어떤 AI든 다룰 수 있음 |
| 서버 | Supabase 무료 플랜 | 서버 코드를 직접 짜지 않기 위해 |
| 로그인 | Supabase 기본 인증 | |
| 기기 연동 | PC 브라우저 · 폰 브라우저 · APK 전부 같은 계정으로 동기화 | 사용자의 1순위 요구사항 |
| **오프라인 동작** | **지원 안 함 — 온라인 전용** | 사용자가 인터넷 없는 상황이 없다고 확인 |
| 순간 끊김 | "저장 실패 → 다시 시도" 안내만 | |
| 백업 | 서버 자동백업이 없으므로 **내보내기/가져오기 기능**으로 대체 | Supabase 무료 플랜 제약 |

### 데이터 설계 원칙 (출시 · 확장 대비)

- 모든 기록에 **ID · 생성시각 · 수정시각 · 사용자ID · 삭제표시(soft delete)** 를 넣는다
- **스키마 버전 번호**를 둔다 — 구조가 바뀌어도 기존 기록이 깨지지 않게
- 이 설계 덕분에 나중에 오프라인 동작을 얹더라도 전체를 갈아엎지 않아도 된다

### 데이터 구조 (예정)

- **exercise** — 운동 종목: 이름, 부위, 장비
- **routine** — 루틴: 이름, 포함 종목과 순서
- **session** — 운동 세션: 날짜, 시작/종료 시각, 메모
- **set** — 세트: 세션ID, 종목ID, 무게, 횟수, (RPE), 순서

## 3. ⚠️ 이 저장소는 공개(Public)입니다 — 반드시 지킬 것

1. **Supabase RLS(행 수준 보안)는 필수.**
   "각 사용자는 자기 기록만 볼 수 있다"는 규칙. 이게 없으면 공개용 키만으로
   남의 운동기록을 볼 수 있다. 설정 후 **실제로 차단되는지 확인**할 것.
2. **관리자 키(service_role)는 코드에 절대 넣지 않는다.** 이 앱 구조상 쓸 일이 없다.
3. 공개용 키(anon key)는 설계상 노출 전제이므로 저장소에 있어도 된다 — 단 1번이 전제.

## 4. 코드 작성 규칙

### theme 파일 (첫 버전부터 적용)

폰트 · 색 · 글자 크기 · 굵기 · 간격 · 모서리 둥글기를 **한 파일에 모은다.**
화면 코드에는 숫자를 직접 쓰지 않고 theme의 이름을 참조한다.

이유가 두 가지다.

1. 사용자가 디자인을 자주 바꾸고 싶어 한다 → 한 줄 수정으로 끝나야 한다
2. **나중에 만들 "앱 내 디자인 수정 기능"의 전제조건**이다 (아래 5장)

### 주석 · 설명

- 파일 맨 위에 **그 파일이 하는 일**을 2~3줄로 (한국어)
- 까다로운 부분에 **왜 그렇게 했는지** 한 줄씩 (한국어)
- `설명/` 폴더에 **흐름 문서** — "저장 버튼을 누르면 무슨 일이 일어나는가"를
  코드가 아니라 이야기로 풀어 쓴 것. 만든 사람이 코드를 못 읽어도 구조를 알 수 있게.
  단, 너무 상세히 쓰면 코드가 바뀔 때 낡으므로 **구조와 흐름 위주**로 쓴다.

### Supabase 설정도 코드로

표 구조와 RLS 규칙은 대시보드에서 클릭으로 만들면 기록이 남지 않는다.
**반드시 SQL 파일로 이 저장소에 남긴다.**

## 5. 나중에 추가할 것 (첫 버전에는 넣지 않음)

### ① 앱 내 디자인 수정 기능

- 앱 설정 화면에서 **폰트 · 글자색 · 크기 · 굵기**를 바꿀 수 있게
- 범위: **전체 일괄 + 미리 지정한 부분별** (모든 요소를 자유롭게는 아님 — 과하다고 판단)
- 어느 부분을 대상으로 할지는 **앱을 시연하면서 그때그때 추가**하기로 함
- 이 설정도 서버에 저장해야 PC·폰에서 동일하게 보임

### ② 검토 후보 (아직 결정 아님)

루틴 · 통계 · 휴식 타이머 · 1RM 추정 · 사진/영상 첨부 · 체중 기록 · 유산소 기록

> 사진/영상은 Supabase 무료 파일 용량(1GB)을 가장 빨리 소진하는 기능이므로 주의.
