## 0. 한 줄 요약

맨몸 운동은 **무게가 고정**이라 3대와 달리 **횟수를 올려** 진행한다.
목표는 **개수 / 시간(초) / 거리(m)** 셋 중 하나. "500개"는 **한 번에 연속 500개**를 뜻한다.
훈련 방식은 **기본 선형(꾸준히 늘리기) 하나만** 쓴다.

## 3. 향상 속도 (횟수 %/4주)

| 20 → 43 | 4주에 **30%** | 12주 |

### 팔굽혀펴기 — 목표 1년 (51주) · **시작값 5회** (09-30 홍겸 님: "5~6개는 할 수 있다")

### 턱걸이 — 목표 2년 반 (124주) · 기본표 그대로

4주에 **25% → 15% → 9% → 5% → 3%** (입문 → 초급 → 중급 → 고급 → 상급)

### ⚠ 이 숫자들의 출처를 분명히 밝힌다

- **고반복(100회 이상) 향상 속도를 다룬 연구는 찾지 못했다.**
- 참고한 것: 6주 팔굽혀펴기 프로그램 남 33.8→49.7회(+47%) [출처 NCJRS 초록] · MTI 3.5주 팔굽 18~35% · 턱걸이 20~49% [출처, 자기보고·표본 작음]. 둘 다 초급 대상 · 짧은 기간.
- **위 표는 홍겸 님이 제시한 기간(스쿼트 2년 · 팔굽 1년)에 맞춰 Claude 가 역산한 값이다.** 턱걸이만 기본표가 우연히 2년 반으로 맞았다.
- → 그래서 5절(향상 데이터 학습)이 이 합의의 핵심이다.

## 4. 턱걸이 — 어시스트 / 과부하 (09-30 홍겸 님 요청)

턱걸이를 **플랜 종목으로 켜면** 옵션 버튼 두 개가 생긴다.

```
[정자세]  [어시스트]  [과부하]      ← 셋 중 하나만 켜진다
```

| 버튼 | 무게 칸에 넣는 값 | 유효 부하 |
|---|---|---|
| 정자세 (기본) | — | 체중 |
| **어시스트** | 보조 무게 | **체중 − 보조** |
| **과부하** | 추가 무게 (원판 · 조끼) | **체중 + 추가** |

### 값이 바뀌면 플랜이 자동으로 다시 계산된다

1. 플랜은 회차마다 **목표 1RM** 을 낸다 (3대와 같은 구조)
2. 오늘 처방 횟수 = `30 × (목표1RM ÷ 유효부하 − 1)` — 에플리 식을 뒤집은 것. 프로젝트 전 종목 에플리 통일과 같다
3. 보조 무게를 줄이면 유효 부하가 올라가 **처방 횟수가 저절로 줄고**, 그게 진도다

**실제 값으로 확인** (체중 109kg · 파이썬으로 계산)

| 상태 | 유효 부하 | 목표 1RM 92kg | 109kg | 120kg |
|---|---|---|---|---|
| 보조 40kg | 69kg | **10.0회** | 17.4회 | 22.2회 |
| 보조 30kg | 79kg | 4.9회 | 11.4회 | 15.6회 |
| 보조 20kg | 89kg | 1.0회 | 6.7회 | 10.4회 |
| 보조 0 (정자세) | 109kg | — | 1회 | 3.0회 |

→ 홍겸 님 현재 기록 **보조 40kg × 10회** 가 1RM 92kg 으로 정확히 맞는다. 식이 실제와 맞음을 확인했다.

### 지킬 것
- **목표(30회)와 수준 판정은 언제나 정자세 기준.** 어시스트/과부하는 오늘 처방을 바꿀 뿐이다
- ⚠ **에플리는 12회를 넘으면 오차가 커진다.** 어시스트 구간 처방은 **5~10회**로 제한한다
- 과부하는 목표 1RM 이 체중을 넘은 뒤에만 의미가 있다 (109kg 초과)
- 팔굽혀펴기에는 이 옵션을 **넣지 않는다** (09-30 홍겸 님 — 무릎 대고 옵션 삭제)

## 5. ★ 향상 데이터 저장 — 나중에 학습하기 위한 기반 (09-30 홍겸 님 요청)

3절 속도표가 추측이므로, **홍겸 님 실제 기록으로 바꿀 수 있게** 기반을 짠다.
**맨몸 3종뿐 아니라 3대·모든 플랜 종목에 같이 넣는다** (데이터를 한곳에 모으려고).

### 측정할 때마다 한 줄씩 쌓는다 — `향상기록[]`

| 칸 | 내용 |
|---|---|
| `날짜` | 측정일 |
| `종목` | 종목 id |
| `측정값` | 정자세 최대 횟수 (또는 무게×횟수) |
| `체중` | 그날 몸무게 |
| `유효부하` | 어시스트·과부하 반영값 |
| `누적횟수` | 직전 측정 이후 그 종목을 한 총 반복 수 |
| `운동일수` | 그 사이 그 종목을 한 날 수 |
| `예상값` | 앱이 예상했던 값 |
| `오차` | 실제 ÷ 예상 |

### 이게 쌓이면 알 수 있는 것

| 알고 싶은 것 | 어떻게 |
|---|---|
| 내 진짜 향상 속도 (%/4주) | 오차를 모아 속도표를 보정 |
| 몇 주마다 오르는지 | 측정 간격별 증가폭 |
| 주 몇 회가 제일 빠른지 | `운동일수` ↔ 향상량 |
| 한 번에 몇 개씩이 좋은지 | `누적횟수` ↔ 향상량 |

### 동작 규칙
- **측정 기록 3개 이상**이 쌓이면 기본표 대신 **내 값**을 쓴다. 그전엔 기본표
- 화면에 지금 무엇을 쓰는지 표시: `기본표` / `내 기록 (n회)`
- **백업 내보내기에 포함한다** → 파일만 주면 Claude 가 분석해 표를 다시 짤 수 있다
- 저장 형식 **스키마 10** 으로 올린다. 옛 파일은 `향상기록` 이 비어 있는 채로 읽힌다

## 7. 확인한 방법

| 무엇 | 어떻게 확인했나 |
|---|---|
| 속도표 → 기간 | 파이썬으로 구간별 계산. 스쿼트 105주 · 팔굽 51주 · 턱걸이 124주 |
| 어시스트 환산식 | 파이썬으로 계산 → 보조 40kg×10회 = 1RM 92kg, 홍겸 님 실제 기록과 일치 |
| 부하 % | 논문 초록 · 요약 두 곳 이상 대조 (출처 아래) |
| **화면** | **확인하지 않았다.** 시안을 만들지 않았고 앱에도 아직 안 들어갔다 |
