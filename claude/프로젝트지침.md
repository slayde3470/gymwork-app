# claude.ai 프로젝트 '운동어플' 지침 (원문 사본 · 2026-10-25)

> 클로드코드로 옮기면서 claude.ai 프로젝트 설정에 있던 지침을 그대로 옮겨 둔 것.
> 클로드코드에서는 이 파일이 자동으로 읽히지 않는다 — CLAUDE.md 에 합칠지 홍겸 님 결정 대기.

이 프로젝트는 안드로이드 운동앱 '하젠하이데'(저장소 slayde3470/gymwork-app)를 만드는 작업이다. 홍겸 님은 코딩 초보다 — 한국어로, 짧게. 불명확한 부분은 먼저 처리할 수 있는 일들을 먼저 처리한 후 질문.

[시작]
1. add_repo(owner="slayde3470", repo="gymwork-app", access="push") → git clone --depth 1 https://github.com/slayde3470/gymwork-app /home/claude/gymwork-app. "권한 없음"이라고 말하기 전에 반드시 먼저 해 본다.
2. 저장소 CLAUDE.md 가 작업 규칙이다. 단 아래 [빠른 길]은 이 지침이 우선한다.
3. 시킨 일에 필요한 문서만 연다(claude/00_색인.md 표대로). 질문·설명·조사만이면 아무것도 읽지 않는다.

[빠른 길 — 토큰 아끼기]
- 작은 수정(표시 10개 미만, 말로 한 한두 가지): 도우미 없이 직접 고친다 → 고친 곳만 확인(사진 1장 / 해당 시험) → 바로 올린다 → 결과부터 알린다.
- 일을 먼저 두 갈래로 가른다(CLAUDE.md 3절 '묶는 법'): ① 모양·동작(ui/만) ② 저장·계산(data/). 섞어서 한 묶음으로 돌리지 않는다.
- ① 모양: 본체가 직접. 화면 3개 이상일 때만 도우미(최대 3명, model "sonnet", 화면 파일이 겹치지 않게). watchdog 없음 — 검사 빌드 + 폰 확인. 끝난 것부터 바로 main → APK, 다른 도우미를 기다리지 않는다.
- ② 저장·계산: 따로 떼어 본체가 직접. watchdog 은 이때만 1번(data 변경 + 그것을 쓰는 화면 경로만).
- 도우미에게는 필요한 것만 골라 넘긴다: 그 화면의 시안 patch 파일 이름 · 요청 원문 · 고칠 파일. 시안 7일체험.html 은 통째로 읽히지 않는다(시안찾기.py).
- 요청·결정은 저장소 문서/작업일지.md 에 한 줄씩 덧붙인다. 프로젝트 문서(claude/…)는 홍겸 님이 "정리해" 할 때 한 번에 옮긴다.
- 한 묶음(시안 한 판 · 앱 한 단계)이 끝나면 새 대화를 권한다.

[시안 — 앱보다 먼저]

- 고칠 때: patch_vNN.py(정확히 맞는 곳만 바꿈) + 확인 스크립트(playwright 389×860) + 사진을 직접 본다.
- "표시해 놨어" → CLAUDE.md 2-1 대로 marks 를 읽는다.
- 시안은 모양만(저장·계산은 앱에서 한 번만). 확인은 바꾼 곳마다 사진 1장 + 핵심 1~2개.
- 계획에 저장·계산이 끼면 '오래 걸림 · 약 N분'과 더 간단한 대안을 먼저 알린다.
